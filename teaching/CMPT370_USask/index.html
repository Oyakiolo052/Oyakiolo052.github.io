Course Overview

CMPT 370 introduces the principles and techniques of software engineering, combining theoretical foundations with practical experience in developing a medium-sized software system as part of a team.

The course covers software development processes, Agile methodologies, requirements engineering, user stories, software design, architecture, quality assurance, testing, technical debt, refactoring, and software maintenance.

A central component is a semester-long group project in which students apply software engineering practices to plan, design, implement, test, and demonstrate a working software product. The course emphasizes not only technical knowledge but also collaboration, communication, project management, and professional responsibility.

Learning Outcomes

Upon successful completion of the course, students should be able to:

Apply Software Engineering Practices

Understand and apply fundamental software engineering concepts, processes, and techniques throughout the software development lifecycle.

Engineer Requirements

Identify, capture, document, and analyze requirements, including user needs, user stories, and system functionality.

Design Software Systems

Translate software requirements into implementable designs using appropriate modeling, architecture, and design principles.

Develop Maintainable Software

Implement software systems while applying clean coding practices, modular design, and maintainability principles.

Apply Quality Assurance

Apply software testing, quality assurance, and maintenance practices to evaluate and improve software systems.

Collaborate in Teams

Develop teamwork, communication, planning, and coordination skills through collaborative software development projects.

Course Topics

The course introduces major software engineering activities across the development lifecycle, from understanding user needs to maintaining and evolving software systems.

Software Engineering Fundamentals

Introduction to software engineering, software development processes, professional responsibilities, and engineering practices for developing software systems.

Agile Software Development

Agile methodologies, Scrum, iterative development, user stories, project planning, and team coordination.

Requirements Engineering

Requirements elicitation, documentation, analysis, user needs, functional requirements, and user stories.

Software Design

Software design principles, system modeling, object-oriented design, interface design, and interactive system design.

Software Architecture

Architectural design, software components, modularity, design decisions, and the organization of software systems.

Software Quality Assurance

Software quality, testing, quality assurance practices, and approaches for identifying and preventing defects.

Refactoring and Software Maintenance

Technical debt, refactoring, software maintenance, software aging, and long-term software evolution.

Generative AI in Software Engineering

The emerging role of generative AI in software engineering, its opportunities and limitations, and responsible human oversight of AI-assisted development.

Teaching and Learning Approach

The course combines theoretical instruction, practical software engineering examples, collaborative activities, and a semester-long group development project.

Lectures

In-person lectures introduce software engineering principles and techniques, supported by practical examples and classroom discussions.

Team-Based Development

Students collaborate in teams of five to develop a medium-sized software product throughout the semester.

Scrum-Style Tutorials

Weekly tutorial meetings allow teams to report progress, discuss obstacles, review deliverables, and receive guidance from teaching assistants.

Project Milestones

Project deliverables encourage students to apply requirements engineering, software design, implementation, testing, and documentation practices.

Project Demonstrations

Teams present their completed software products, answer technical questions, and demonstrate their implementations.

Feedback and Support

Students receive feedback through tutorial meetings, project presentations, course discussions, and instructor communication.

Semester-Long Software Development Project

A major component of CMPT 370 is a collaborative project where students work in teams of five to plan, design, implement, and demonstrate a software product of their choosing.

The project provides practical experience with the challenges of real-world software development, including understanding user requirements, making design decisions, coordinating team members, implementing features, and evaluating software quality.

Project Planning

Define the product idea, identify potential users, establish project scope, and plan development activities.

Requirements and User Stories

Identify user needs, document requirements, and organize functionality into user stories and epics.

Design and Implementation

Translate requirements into software designs, implement features, and integrate individual contributions into a working system.

Testing and Documentation

Test the software, document the implementation, and prepare project artifacts for evaluation.

Team Coordination

Participate in weekly Scrum-style meetings, communicate progress, resolve issues, and document individual contributions.

Final Presentation and Demo

Present the completed product, explain engineering decisions, answer questions, and demonstrate the working system.

Project-Based Learning

The project emphasizes the practical application of software engineering concepts and the development of collaborative problem-solving skills. Students experience how requirements, design, implementation, testing, and documentation must work together to produce a coherent software system.

Responsible Use of Generative AI

Recognizing the increasing role of generative AI in software development, the course established guidelines for responsible and transparent use of AI tools in student projects.

Students were permitted to use generative AI as a supplementary learning and brainstorming resource, provided that its use did not replace the core learning activities of software engineering.

Permitted Uses

Brainstorming ideas, exploring alternative designs, understanding programming syntax, explaining concepts, investigating errors, and obtaining support for debugging and basic test generation.

Restricted Uses

Generating complete solutions or significant portions of project logic, preparing graded milestones with AI, submitting code without understanding it, concealing AI usage, or substituting AI for teamwork.

AI Usage Documentation

Project deliverables required an AI usage statement documenting when AI tools were used and how they supported the development process.

Human Accountability

Students remained responsible for understanding, validating, and explaining their implementations and engineering decisions.

Educational Objective

The objective was to help students recognize AI as a supporting tool while preserving independent technical understanding, engineering judgment, academic integrity, and meaningful team collaboration.

Teaching Reflection

Teaching CMPT 370 provided opportunities to connect foundational software engineering principles with practical, team-based software development.

The semester-long project highlighted the challenges students face when translating requirements into working software, coordinating contributions, and making engineering decisions.

The course also offered an opportunity to explore how responsible AI use can be incorporated into software engineering education without replacing independent learning, critical reasoning, and human accountability.

Reflection on Student Feedback

Student feedback highlighted the value of practical team projects, relevant examples, instructor approachability, and opportunities to develop software engineering and collaboration skills.

Students also identified opportunities to improve the organization and pacing of lectures, clarify project deliverables and assessment expectations, and provide stronger connections between theoretical concepts and practical project activities.

Feedback on instructional materials, including the use of AI-generated illustrations, emphasized the importance of clear, carefully reviewed educational resources and meaningful student engagement.

These observations provide direction for refining instructional materials, improving project guidance, introducing more targeted learning activities, and supporting effective collaboration in future course offerings.
